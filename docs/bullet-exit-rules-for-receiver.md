# Памятка приёмнику сигналов Crypto Alt Bullet

Это описание правил **новых long-сигналов**, которые Bullet отправляет для паттернов `liquidation_cascade`, `balanced_grind`, `price_led_momentum` и `impulse_buy`. Не применять автоматически к старым позициям. Версия передаваемых правил: `bullet-long-exits-v2`.

## Общее для всех четырёх паттернов

1. Вход — market. Начальный стоп — **конкретное значение `stopLoss` из сигнала**; не заменять его универсальным процентом.
2. Все проценты ниже — **движение цены от фактической цены исполнения входа**, без умножения на плечо; это не R-множители.
3. При достижении **+5%** перенести стоп на исходную цену входа (БУ без учёта комиссий). Для `BTCUSDT` порог БУ — **+1%**.
4. Для альткоинов при достижении **+10%** защитить **+5% от входа** стопом. Первая цель +10% — событие, **не приказ закрыть всю позицию**.
5. Для альткоинов при достижении **+15%** включить трейлинг: защищённая прибыль = максимальный достигнутый процент прибыли от входа **минус 10 процентных пунктов**. Например, после пика +24% уровень стопа соответствует +14% от входа. Стоп никогда не понижается. При срабатывании закрывается оставшаяся часть позиции.
6. Если обычная позиция не закрылась раньше, по истечении **4 дней** закрыть её по наблюдаемой рыночной цене.
7. Уведомление о возможной фиксации **20–25%** на этапах роста альткоинов — только рекомендация. Bullet не подтверждает и не исполняет такую частичную пользовательскую заявку. Не считать её уже исполненной.

**BTC исключение:** после пика +1% стоп на фактическую цену входа (Б/У); после пика +2% включить трейлинг на **1 процентный пункт прибыли от входа ниже максимального достигнутого пика**. Пик +2% → стоп +1%; пик +3% → стоп +2%; дальше уровень растёт вместе с пиком и никогда не снижается. В `payload.exitRules` для BTC это дополнено `progressMilestoneIntervalPct: 1`. Это одна позиция без нового core/runner-разделения. BTC-уведомления о каждом целом проценте — уровни сопровождения, а не фактические частичные продажи. Правила +10%/+5% и +15%/10 п.п. выше к BTC не применять.

Для первых трёх паттернов (`liquidation_cascade`, `balanced_grind`, `price_led_momentum`) дополнительных отличий в этих правилах выхода нет.

## Дополнение для `impulse_buy` (альткоины и старые позиции с уже закрытым core)

- Основная часть (**core**) — 80%; остаток (**runner**) — 20%.
- Core следует общим правилам и закрывается по обычному трейлингу. **После закрытия core трейлингом** для runner действует аварийный стоп на исходной цене входа.
- При пике runner **+30%** включить его отдельный трейлинг: максимум прибыли от первоначального входа минус **30 процентных пунктов**; стоп не понижается.
- Runner истекает через **120 часов от первоначального входа** и тогда закрывается по наблюдаемой рыночной цене, если не закрылся раньше.

## Что не нужно делать

- Не заменять это собственной схемой `TP1 +1R / TP2 +2R / TP3 +3R` и трейлингом 5%.
- Не выставлять фиксированный полный take-profit на +10%.
- Не считать получение HTTP `202` доказательством исполнения правил: оно может означать только постановку сигнала в очередь. Сначала проверить обработку версии и сценарии выхода в paper-режиме; реальные заявки не включать на основании одной этой памятки.

Эта памятка предназначена для передачи человеку или агенту второго проекта. Endpoint `/api/trading/signals` принимает **сигналы, а не отдельный текст стратегии**. После публикации обновлённого Bullet поля `payload.rulesVersion` и `payload.exitRules` будут сопровождать каждый **новый подходящий** исходящий сигнал, но приёмник должен явно поддерживать их; уже сохранённые сигналы не меняются.
