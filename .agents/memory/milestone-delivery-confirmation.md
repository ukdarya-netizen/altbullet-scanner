---
name: Milestone delivery confirmation
description: Durable rule for milestone alerts when Telegram delivery fails or two workers run concurrently.
---

Milestone price events must be committed to the trading state immediately, while Telegram delivery is tracked durably per recipient. Retry explicit retryable rejections; 403 and invalid-recipient 400 errors are terminal/unavailable and must not wedge later milestones. A direct-chat timeout/network uncertainty remains at-most-once, but a public channel timeout or expired send lease must retry after backoff: a rare duplicate is preferable to a permanently missed channel milestone.

**Why:** Updating `last_milestone` before Telegram delivery prevented duplicate alerts but turned a timeout, empty target list, or API failure into a permanent lost notification. A single aggregate delivery state also retried successful recipients when another target failed. The Telegram Bot API cannot reliably prove that a timed-out channel request was accepted, so channel availability takes priority over exact-once delivery. Moving the trading state after delivery would instead risk losing protection such as breakeven or trailing stop. Neutral reclassification is a separate race: fast-cycle milestone recovery is not serialized by the normal market-cycle lease, and a claimed recipient can cross a status correction before its external send.

**How to apply:** New milestone paths must atomically advance the economic milestone cursor and create the immutable outbox event/recipient snapshot in one transaction. A pending legacy milestone must block newer milestone claims so its single mutable slot cannot be overwritten. Each recipient attempt needs a fenced claim identity so an expired worker cannot overwrite a newer result. Reclaim only the undelivered channel recipient after ambiguous/expired processing; never reclaim `delivered`, and keep direct-chat ambiguity at-most-once. Economically required stop or trailing closure still proceeds immediately, but must not erase pending fields: the milestone outbox must already be durable before the cursor commits, so terminal close cannot orphan it. When neutralizing a position, coordinate with the send boundary itself, not just the initial claim or market-cycle lease; preserve in-flight/ambiguous audit, abandon only confirmed unsent or retryable rows, and prevent a sender holding an old claim from sending after the neutral cutover.
