---
name: Task agent batch-commit risk
description: Task агент смешивает несвязанные изменения в один коммит/merge — известный системный риск.
---

**Правило:** Task агент склонен объединять несвязанные правки в один коммит и один merge-batch. Это создаёт риск: отклонение merge по одной задаче тянет за собой отклонение несвязанных правок из того же batch.

**Задокументированные случаи:**
1. GL/OH pipeline shutdown (2026-08-08) — range-delete в watcher.ts задел 405 строк коллатерального кода (`_runLiqCascadeFireCycle` + TA scanner infra), потому что агент не проверил, что между "ненужными" функциями сидит нужный код.
2. Task #228 (2026-08-13) — BA OI30m анализ и несвязанные правки смешаны в один commit/merge. Когда merge отклонили по BA, за ним отменили и task #229 (LC ob_ratio), хотя они независимы.

**Why:**
Task агент оптимизирует под "закрыть задачу", а не под "минимальный diff". Он читает весь контекст открытых задач и может незаметно включить попутные правки, которые кажутся ему "очевидно нужными".

**How to apply:**
- Критические или спорные задачи давать task-агенту ИЗОЛИРОВАННО — одна задача = один merge.
- При отклонении merge от task-агента немедленно проверять, не упали ли за ним несвязанные согласованные изменения.
- Если task-агент сделал batch — проверить git diff коммита, перечислить все фактически изменённые файлы.
- Для согласованных изменений, не требующих анализа (soft penalty, threshold tweak по готовым данным) — реализовывать напрямую через main agent, не через task-агента.
